SAFE RETRY LOGIC

Implement retries ONLY for a transaction that is CONFIRMED to have failed.

Use:

MAX_ATTEMPTS=3

as the default example.

The retry count must be configurable.

Use exponential backoff:

delay = min(
RETRY_BASE_DELAY_MS * 2^(attempt - 1),
RETRY_MAX_DELAY_MS
)

For example:

Attempt 1 → failure
↓
wait 2 seconds
↓
Attempt 2 → failure
↓
wait 4 seconds
↓
Attempt 3 → failure
↓
STOP

Do not exceed "MAX_ATTEMPTS".

A retry is permitted ONLY when:

The blockchain definitively establishes that the previous mint attempt failed/reverted, and there is no successful transaction associated with that attempt.

Before retrying:

1. Check transaction receipt/status.


2. Confirm the transaction reverted or definitively failed.


3. Confirm no successful mint occurred.


4. Re-check current NFT balance.


5. Re-check wallet mint limit.


6. Re-check public mint status.


7. Re-check contract pause status if available.


8. Re-check sold-out status if available.


9. Re-estimate gas.


10. Re-check maximum gas cost.


11. Confirm there is no pending/unknown transaction.


12. Confirm target remains 1.


13. Only then submit the next attempt.



NEVER retry if:

Transaction is pending.

Transaction status is unknown.

RPC timed out after submission and transaction status has not been resolved.

Transaction hash exists but receipt cannot yet be determined.

The transaction succeeded.

NFT balance increased.

Wallet limit has been reached.

Public mint closed.

Collection is sold out.

Contract is paused.

Gas safety check fails.

Required mint authorization is unavailable.

Maximum attempts have been reached.


If transaction status is uncertain:

STOP

and notify Telegram that manual blockchain-status resolution is required.

Never guess.
